# sukasuka-vocal-dataset-builder 角色语音训练解释书

更新时间：2026-07-01

## 1. 这个项目是什么

`sukasuka-vocal-dataset-builder` 是一个角色语音数据集构建工具。它的核心用途不是直接合成语音，也不是训练模型，而是基于视频文件和 `.ass` 字幕切分出角色台词音频，再通过人工标注把音频归到具体角色名下，最终整理成可供 PITS、VITS、Diffusion TTS、SVC、GPT-SoVITS 等语音模型使用的数据集。

简单说：

- 它解决的是“从素材里整理出训练数据”的问题。
- 它不解决“训练模型”和“推理部署”的问题。
- 它对后续自训练很有价值，因为角色语音模型最耗时间的部分往往不是按下训练按钮，而是找素材、切音频、清洗、校对、标注和排除污染样本。

项目 README 明确提醒：仓库 Python 代码是 MIT License，但动画、字幕、Python 依赖、音频素材等可能有各自授权限制。因此如果后续要公开演示、发布模型或商用，必须单独确认素材和角色权利。

参考：

- https://github.com/Hecate2/sukasuka-vocal-dataset-builder
- https://github.com/RVC-Boss/GPT-SoVITS
- https://github.com/RVC-Boss/GPT-SoVITS/blob/main/api_v2.py

## 2. 你需要准备什么

### 2.1 合法可用的声音素材

优先级从高到低：

1. 自己录制或获得授权的角色语音素材。
2. 可明确用于研究 / 非商业的公开语音数据。
3. 仅用于本地私下实验的动画、游戏、广播剧素材。

不建议把未授权角色模型用于公开发布、商用 Demo、公开视频或可下载服务。即使 GitHub 上有现成角色模型，也常常只适合本地研究和非商业测试。

### 2.2 字幕或转写文本

最好准备 `.ass` 字幕，因为该项目主要围绕字幕时间轴切分音频。

理想字幕要求：

- 时间轴准确，台词开始和结束不要偏太多。
- 能区分说话角色，或者至少方便人工补角色名。
- 文本和实际发音基本一致。
- 不要混入旁白、音效、歌词、叠声和多人同时说话。

如果只有音频没有字幕，你需要先用 ASR 转写，再人工修正。

### 2.3 干净的人声音频

训练最怕脏数据。需要尽量排除：

- 背景音乐太重的片段。
- 爆炸、脚步、环境声、掌声等非人声。
- 多角色同时说话。
- 极端尖叫、哭喊、笑声过多、气息声过重。
- 字幕和声音错位明显的片段。

可以用 Demucs、UVR 等工具做人声分离，但分离后的声音也要人工听检，因为分离伪影会污染模型。

### 2.4 每个角色的数据量

粗略建议：

- 5-10 分钟干净语音：能做最小实验，声音像不像不稳定。
- 20-40 分钟干净语音：可以训练出比较可用的单角色 TTS。
- 1-2 小时干净语音：更适合追求稳定音色、语气和长句质量。
- 2 小时以上：继续提升会变慢，数据质量比数量更重要。

对车载助手这种短句播报场景，20-40 分钟高质量数据通常比 2 小时混杂数据更划算。

### 2.5 训练环境

最低准备：

- Python 3.10 或 3.11 环境。
- ffmpeg。
- Git。
- 语音模型训练框架，例如 GPT-SoVITS。
- 一个能存放音频、模型、日志和 checkpoint 的目录。

硬件建议：

- Mac 可以做数据整理、音频切分、听检和 Web 接入。
- 真正训练更建议用 NVIDIA GPU。
- 8GB VRAM 可以做小规模实验，但会慢且容易受 batch 限制。
- 12-24GB VRAM 更适合训练 GPT-SoVITS / VITS 类模型。
- 如果只做推理，本地电脑压力会小很多；如果要低延迟车载交互，最好让 TTS 服务常驻并预热模型。

## 3. 推荐工作流

1. 收集合法素材，记录来源、授权、角色、语言和时长。
2. 准备 `.ass` 字幕或转写文本。
3. 使用 `sukasuka-vocal-dataset-builder` 按字幕切出音频片段。
4. 手动标注角色，修正 `meta.csv`。
5. 删除脏片段，包括非人声、多人重叠、音乐过重、情绪极端和字幕错位片段。
6. 按角色导出训练集和验证集。
7. 用 GPT-SoVITS 或类似框架训练 / 微调。
8. 选择稳定参考音频，导出模型权重和配置。
9. 启动本地 TTS API，例如 GPT-SoVITS 的 `api_v2.py`。
10. 让当前车载助手通过本地 `/api/tts` 代理调用角色语音。

建议目录形态：

```text
voice-lab/
  sources/
  subtitles/
  raw-clips/
  cleaned-clips/
  datasets/
    character-a/
      train/
      val/
      manifest.json
  models/
    character-a/
      gpt.ckpt
      sovits.pth
      ref.wav
      manifest.json
```

## 4. 训练一个角色大约要多少钱

以下是工程估算，不是固定报价。真实成本会随 GPU 租赁平台、模型版本、数据量、训练轮数和返工次数变化。

### 4.1 软件成本

开源工具本身通常免费：

- `sukasuka-vocal-dataset-builder`：开源数据集构建工具。
- GPT-SoVITS：开源少样本语音克隆 / TTS 工具。
- ffmpeg、Demucs 等：常见开源音频工具。

真正的成本主要在人工清洗和 GPU 计算。

### 4.2 人工时间成本

小实验：

- 5-10 分钟干净语音。
- 素材整理和听检约 2-6 小时。
- 训练与调参约 1-3 小时。

可用角色：

- 20-40 分钟干净语音。
- 素材整理和听检约 6-20 小时。
- 训练与调参约 3-8 小时。

较高质量角色：

- 1-2 小时干净语音。
- 素材整理和听检约 20-60 小时。
- 训练、评估和返工约 8-24 小时。

经验上，数据清洗比训练更影响最终效果。

### 4.3 GPU 费用粗估

如果租云 GPU：

- 入门实验：约 1-3 GPU 小时。
- 20-40 分钟可用角色：约 3-8 GPU 小时。
- 1-2 小时高质量角色：约 8-24 GPU 小时。

按常见 3090 / 4090 / A10 等租赁价格粗略估算：

- 入门实验：约 5-30 元人民币。
- 可用角色：约 20-100 元人民币。
- 较高质量角色：约 80-300 元人民币或更高。

这些数字只包含训练算力，不包含人工时间、素材授权、存储和返工成本。

### 4.4 存储成本

单角色通常不大：

- 清洗后音频：几百 MB 到数 GB。
- 训练中间产物和 checkpoint：10-50GB 更稳妥。
- 多角色、多版本实验需要更大的磁盘空间。

## 5. 质量验收标准

一个角色语音模型可以进入车载助手测试前，建议满足：

- 至少 20 分钟以上干净有效语音，越干净越好。
- 文本与音频匹配率大于 95%。
- 没有明显背景音乐、环境声和多人重叠。
- 普通短句推理稳定，不频繁吞字、爆音、断句异常。
- 车载常用句式自然，例如确认、拒绝、提醒、追问、简短建议。
- 生成 3-8 秒语音的延迟可以接受。
- 有模型卡片，写清来源、训练方式、限制和授权状态。

## 6. 当前车载助手怎么接入

本项目当前优先级不是马上训练，而是先把“可替换的本地 TTS Adapter”接好。

原因：

- 训练角色模型前，先确认车载助手能稳定调用本地 TTS。
- 先打通 `文本回复 -> 本地 TTS 服务 -> 音频播放 -> 暂停 / 继续 / 停止 -> 失败兜底` 链路。
- 之后无论换成 GPT-SoVITS、Style-Bert-VITS2、Fish Speech 还是你自己训练的模型，前端和 Agent Runtime 都不需要大改。

当前推荐接入方式：

1. 车载助手前端生成自然语言回复。
2. 前端调用本项目固定地址 `/api/tts`。
3. `local-agent-server.mjs` 把请求代理到本机 GPT-SoVITS 服务。
4. GPT-SoVITS 返回音频。
5. 前端用 HTMLAudioElement 播放，支持暂停、继续和停止。
6. 如果本地角色 TTS 未配置或失败，自动回退浏览器 `speechSynthesis`。

GPT-SoVITS 官方 API 文档中，`api_v2.py` 默认可启动在 `127.0.0.1:9880`，推理 endpoint 是 `/tts`，POST 请求需要 `text`、`text_lang`、`ref_audio_path`、`prompt_lang` 等字段。

## 7. 本项目当前的最小配置

如果你已经有 GPT-SoVITS 服务和参考音频，可以这样启动当前车载助手：

```bash
NIO_GPT_SOVITS_ENDPOINT=http://127.0.0.1:9880/tts \
NIO_GPT_SOVITS_REF_AUDIO_PATH=/absolute/path/to/ref.wav \
NIO_GPT_SOVITS_PROMPT_TEXT="这段参考音频对应的原文" \
NIO_GPT_SOVITS_PROMPT_LANG=zh \
NIO_GPT_SOVITS_TEXT_LANG=zh \
node local-agent-server.mjs 4173
```

然后打开：

```text
http://127.0.0.1:4173/
```

如果没有配置 `NIO_GPT_SOVITS_REF_AUDIO_PATH`，当前项目应该不会报错卡死，而是自动使用浏览器语音兜底。

## 8. 我的建议

短期：

- 先不要自己训练。
- 先用一个授权状态清晰、只本地测试的 GPT-SoVITS 角色模型验证链路。
- 把当前车载助手的 TTS Adapter、暂停按钮、失败兜底和语音状态跑稳定。

中期：

- 用 `sukasuka-vocal-dataset-builder` 做一次小规模数据集实验。
- 目标先放在 20-40 分钟高质量单角色数据。
- 训练一个只服务本地车载助手短句播报的角色声线。

长期：

- 如果要真实上车或公开展示，改用自有授权声音、品牌定制声音或明确可商用的声音模型。
- 角色声线模型只作为本地 TTS Adapter 的一个实现，不应耦合进 Agent Runtime、安全网关或车辆执行链路。
